# Agent Note: 子进程 spill 故障降级

Status: implemented

[English](2026-09-15-subprocess-spill-fault-degradation.md) | 中文

## 问题

一个长期运行的宿主进程（在 `dsh web` 中观察到）因 stderr 收集器流回调内的 `openSync` 抛出未捕获的 `ENOENT` 而崩溃。每进程私有 spill 目录在首次 spawn 时创建一次；该进程存活期间，目录被 OS 临时目录的外部清理删除，随后某条被收集流首次溢出时尝试在已不存在的目录中打开 spill 文件。异常从流的 `data` 事件逃逸，成为未捕获异常，杀死了整个宿主进程——一次尽力而为的输出恢复失败产生了宿主级的爆炸半径。

## 决策

在 `dsh-subprocess-local` 中，创建与写入 spill 文件不再可能从流回调中抛出。`OutputCollector.openSpillFile` 先在私有目录中以随机名打开文件；任何打开故障都会用 `mkdirSync`（recursive、`0o700`）重建目录，并用新的随机名重试一次。该目录可以安全重建：随机命名、进程私有、仅属主可访问。第二次打开故障、回填已收集块时的故障、或任意逐块 `writeSync` 故障，都会把该流降级为仅保留内存尾部：收集器丢弃不完整的 spill 并停止宣传 `spillPath`，与 `seal` 中最终关闭失败的既有容错规则一致。保尾内存缓冲始终保留，因此输出读取仍然可用，宿主进程继续服务。

## 考虑过的替代方案

**每次打开故障时删除并重建目录，不做重试。** 不予采用：目录重建成功后文件已打开，额外的删除路径会在写入期间危及已打开文件的目录且毫无收益。

**用一个持久内存标志吞掉所有 spill 错误、不重试。** 不予采用：外部临时目录清理是长期运行宿主上反复发生的事件，而目录重建廉价且安全；因一次瞬时故障就永久失去完整输出恢复是不必要的损失。

**在宿主进程中挂全局 `process.on('uncaughtException')` 处理器。** 不予采用：它会掩盖任意回调中的其他同步抛出并隐藏真实 bug；本修复关闭的崩溃路径是流回调内唯一未容错的 spill I/O。

## 后果

无法创建或写入 spill 文件的流仍以截断的内存尾部结算且不携带 `spillPath`，与最终关闭失败完全一致。这类流的 `readFrom` 只是无法从 spill 文件恢复 lossy 区间。已完成的 spill 文件不受影响。重建的目录保持仅属主 `0o700` 权限，共享临时目录的符号链接植入与路径预测防御不变。临时目录确实不可写的宿主对该流失去完整输出恢复，而不再失去整个进程。

## 验证

[spawn 规范](../../../../packages/subprocess/subprocess-local/tests/spawn.spec.ts)中的 `node:fs` 故障注入 mock 新增了 `failNextOpen` 与 `failNextWrite` 计数器。新增 spec 覆盖：首次溢出前被删除的 spill 目录会被重建，且完整流经真实 `spawnSubprocess` 端到端仍可恢复；连续两次打开故障降级为尾部且无 `spillPath`；回填写入故障与流中途写入故障各自降级为尾部并停止宣传路径。本宿主上包内全部 105 个测试通过。

本修复关闭的崩溃已在 Windows 上的 `dsh web` 宿主中复现：崩溃运行的 `dsh-subprocess-*` 目录已不在临时目录中，而同级的每进程目录仍在，证实了外部删除这一触发源。
